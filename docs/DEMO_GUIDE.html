So sánh thêm các tình huống bảo mật

Ngay trên trang đăng nhập, chọn Demo injection → Payload demo → Kịch bản mô phỏng. Chọn một tình huống rồi bấm So sánh kết quả. Phần này dùng bản ghi hư cấu và mã HTTP minh họa.

  1. Lộ bản ghi ngoài phạm vi. Đối chiếu số bản ghi và nhóm sở hữu ở hai kết quả.
  2. Sửa ngoài phạm vi và sửa hàng loạt. Chỉ rõ mã bản ghi được yêu cầu, mã thực sự thay đổi trong mô phỏng và số bản ghi bị ảnh hưởng.
  3. Xóa nhiều bản ghi và mất bảng hoặc bộ sưu tập. So sánh dữ liệu ban đầu với kết quả. Dùng Đặt lại mô phỏng để quay về bộ dữ liệu minh họa.
  4. Thay đổi quyền. So sánh tên hiển thị và vai trò của tài khoản mẫu sau thao tác.
  5. Lộ chi tiết qua lỗi và khác biệt phản hồi. Giải thích loại thông tin mà mỗi phản hồi có thể làm lộ.
  6. Xác thực và kiểu dữ liệu MongoDB. Giải thích vì sao cần kiểm tra mật khẩu và kiểu dữ liệu trước khi cấp phiên.
  7. Quyền xem yêu cầu và hành động bị cấm. Đối chiếu kết quả của sinh viên với thao tác dành cho quản trị viên.
  8. Phiên và dữ liệu hợp lệ. So sánh phiên còn hiệu lực với phiên không được chấp nhận. Mở lại yêu cầu mẫu để kiểm tra dấu nháy trong tiêu đề.

Để đối chiếu với kết quả thực tế, đăng nhập bằng tài khoản sinh viên, mở Nhật ký & demo → Kiểm tra trên CampusDesk và chạy Kiểm tra quyền đọc của sinh viên. Đọc mã HTTP dự kiến và thực tế cho quyền xem yêu cầu của mình và quyền xem nhật ký quản trị. Bấm Tải kết quả JSON để lưu bằng chứng. Tệp đánh dấu simulation cho mô phỏng và live-api cho kiểm tra API thực tế.

Demo bắt buộc MongoDB trước trong khoảng 5 phút

  1. Mongo Unsafe (3003): đăng nhập admin đúng, đăng xuất; nhập mật khẩu sai để thấy 401.
  2. Chọn Demo injection → $gt; quan sát password object, gửi request và mở Người dùng để chứng minh quyền admin thật.
  3. Đăng xuất; nhập payload tùy chỉnh dạng chuỗi JSON có dấu nháy để thấy 401. Object và chuỗi không giống nhau.
  4. Mongo Safe (3004): cùng object $gt → 400, diagnostic ghi chưa chạy truy vấn xác thực. Mật khẩu sai dạng chuỗi → 401; mật khẩu đúng vẫn thành công.
  5. Mở code walkthrough, chỉ ra loginInput, unsafeLogin và verifyPassword. Giải thích session/audit vẫn dùng DB khi credential lookup bị chặn.

Phần so sánh mở rộng nếu còn thời gian

  1. Đăng nhập student: dashboard cá nhân, tạo yêu cầu. Cho thấy user không có trang quản lý tài khoản.
  2. Đăng xuất; đăng nhập admin bằng mật khẩu đúng: dashboard toàn hệ thống, xử lý yêu cầu và tài khoản.
  3. SQL Unsafe: sai mật khẩu bị từ chối; chọn Demo injection → OR luôn đúng hoặc comment → vào dashboard admin mà không cung cấp mật khẩu đúng.
  4. SQL Safe: gửi cùng preset → bị chặn; mật khẩu đúng vẫn hoạt động.
  5. Mongo Unsafe: gửi password object {"$gt":""}; tiếp tục $ne, $regex và các toán tử còn lại nếu có thời gian → session admin thật.
  6. Mongo Safe: cùng object bị HTTP 400; input chuỗi sai bị 401; mật khẩu đúng vẫn đăng nhập.
  7. Vào Nhật ký & demo để giải thích query shape, metadata và khác biệt; mở evidence report để đối chiếu test.

Điểm cần giải thích

SQL Injection thay đổi cú pháp/điều kiện SQL do nối chuỗi. NoSQL Injection thay đổi cấu trúc predicate dù không có cú pháp SQL. Bypass đăng nhập vào một tài khoản admin là authentication failure; không phải việc user bình thường được phép gọi API admin.

Payload SQL được kiểm thử

Password: ' OR '1'='1' -- 
Username: admin' -- 
Password: ' OR 1=1 #
Username: ' OR role = 'admin' --

Dấu cách sau -- quan trọng trong MySQL. Demo tab có preset để tránh lỗi gõ.

Giới hạn cần giải thích

Payload chỉ thay điều kiện password nên username không tồn tại vẫn thất bại. Sáu toán tử được giới hạn cho bài lab; không bảo đảm bypass mọi MongoDB app. Hash đơn thuần không đủ nếu vẫn xác thực bằng một query do client thay đổi. CSRF và rate limit không sửa injection; authorization giới hạn quyền sau khi danh tính được xác thực. Ở safe, chưa chạy truy vấn xác thực không có nghĩa là session store/audit không truy cập DB. Lab dùng HTTP local, secret và dữ liệu synthetic, không phải cấu hình production.

Recovery

Nếu CSRF/phiên cũ: reload. Nếu DB down: mở health/log, khởi động lại đúng service. Không sửa payload hoặc mock kết quả để báo thành công.

Chỉ dùng dữ liệu giả lập tại localhost. Tài liệu v1 lưu ở legacy/.
