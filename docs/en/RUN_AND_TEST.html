Run, test, and troubleshoot

Requirements

Install Docker Desktop and start its engine. For host-side checks, use Node.js 22.12 or newer and npm. The Docker setup supplies MySQL and MongoDB; do not install or configure separate database servers.

Start all four applications

git clone https://github.com/kiet1i38/modern-database-attacks.git
cd modern-database-attacks
docker compose up -d --build --wait --wait-timeout 240

Open ports 3001–3004 as listed in the project overview. Demo credentials: admin / Admin@123, student / Student@123, and student2 / Student2@123. Startup seeds only empty databases.

Run checks

npm ci
npm test
npm run test:legacy
npm run test:i18n
npm run build
npm run test:integration

The integration suite exercises real HTTP APIs against the four Docker variants with synthetic data and writes JSON/log results under evidence/. It creates QA accounts and tickets. Do not reset a database containing work you want to keep.

Troubleshooting

  • If a port is busy, identify the process using ports 3001–3004 before stopping anything.
  • If an app is unhealthy, inspect docker compose ps and docker compose logs sql-unsafe (or the affected service) before rebuilding.
  • If the browser reports a database connection error, wait for database health and inspect that service's logs.
  • For a stale UI, rebuild the application containers and reload the page.

Data warning: docker compose down -v and the db:reset commands delete demo data. Use them only when you explicitly intend to clear the local lab.
