Safe and unsafe variants

What the lab compares

  • SQL Unsafe: the login demo composes a SQL predicate using supplied input.
  • SQL Safe: validates scalar input, uses a parameterized username lookup, and verifies a scrypt hash.
  • MongoDB Unsafe: allows a bounded set of teaching operators to reach a password predicate.
  • MongoDB Safe: rejects non-string credentials before lookup and verifies a scrypt hash.

Shared protections

Normal business APIs use parameterized SQL or server-built MongoDB fields. Backend checks enforce roles, active accounts, ticket ownership, CSRF, session rotation, and same-origin writes. Diagnostics redact ordinary credentials and only label recognized demo presets.

Safe demo boundaries

The unsafe login endpoints are intentionally vulnerable for a controlled course demonstration. Use synthetic seeded data only, isolate the variants, and never reuse demo passwords or connect real users. Do not interpret a successful lab bypass as permission to access any other system.

For implementation details, see Code and security flow.
