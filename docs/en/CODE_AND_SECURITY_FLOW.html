Code and security flow

Request path

Browser → JSON parser → session and CSRF checks → domain validation → selected repository method → authentication decision → rotated session. Backend authorization then checks the current database user, role, and ticket owner for each protected route.

MongoDB Unsafe teaching path

await users.findOne({ username, password });

A non-string password accepted by the bounded lab validator can become part of the predicate. The teaching behavior is isolated to unsafe login and seeded synthetic data.

Safe login path

const candidate = await repo.userByUsername(input.username);
const user = candidate && verifyPassword(input.password, candidate.passwordHash) ? candidate : null;

The safe path rejects object values before credential lookup, fetches by username, and verifies the submitted scalar password against a salted scrypt hash. SQL Safe also uses a parameterized query.

Diagnostics

Diagnostics report JSON input type and whether the credential lookup ran. The query template is a source-level explanation, not a profiler trace. Only recognized payload presets receive a payload label; ordinary username/password values are redacted. Localized descriptions use stable keys so language changes do not alter the evidence fields.
