Four Vercel demo variants

Each variant has its own Vercel project and database. This deployment uses branch demo_updated. Open a stable alias:

  • SQL Unsafe
  • SQL Safe
  • MongoDB Unsafe
  • MongoDB Safe

Add ?lang=vi for Vietnamese. The language selector updates the URL and remembers the choice on each host.

Project configuration

All four projects use the repository root, the Other framework preset, the configured Node.js runtime, npm run build:vercel, and dist output. Set one fixed VARIANT per project: sql-unsafe, sql-safe, mongo-unsafe, or mongo-safe. Vercel routes API requests through api/index.js.

Production projects use their existing Production environment settings. Keep database connection strings, session secrets, cookies, passwords, and tokens out of Git, screenshots, and logs. Deployment does not reset or reseed the databases.

Post-deployment checks

  1. Open /api/health and /api/config on each alias; confirm API readiness and the configured variant/database type.
  2. Open the app with ?lang=en and ?lang=vi; sign in with synthetic accounts, switch language, and check role-specific dashboards.
  3. Check cross-variant links, logout, and session isolation between projects.
  4. Use synthetic data only. The two Unsafe variants deliberately demonstrate vulnerable login behavior; never enter real accounts or sensitive records.

A successful build does not prove that an API can reach its database. If health checks fail, inspect Production environment configuration and provider status. The app does not expose connection details to the browser.
