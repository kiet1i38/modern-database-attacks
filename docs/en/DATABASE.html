Stored data

  • Users: unique username, display name, role, contact fields, active state, and password representation.
  • Tickets: owner, title, description, category, priority, status, and timestamps.
  • Sessions: server-side session ID and expiry. MongoDB uses TTL cleanup; SQL checks expiry and cleanup.
  • Audit: actor, outcome, recognized payload label, and timestamp. Passwords and CSRF tokens are not recorded.

Password storage and seed behavior

Safe variants store salted scrypt hashes and no plaintext password. Unsafe variants deliberately use synthetic comparable credentials so a database predicate can demonstrate the lesson. Never add real accounts or personal data.

Startup seeds an empty database only. Reset commands delete users, tickets, sessions, and audit data for the selected database.
