Architecture and request flow

Components

  • frontend/: React, TypeScript, Radix UI, and Vite.
  • src/campus/domain.js: input validation, seed definitions, diagnostic classification, and demo payload catalog.
  • src/campus/repository.js: MySQL and MongoDB repository adapters, session persistence, and audit writes.
  • src/campus/app.js: HTTP routes, authentication, CSRF, authorization, and locale-aware responses.
  • src/campus/server.js: startup, graceful shutdown, and local-lab guard.
  • tests/campus/ and scripts/test-campus-api.js: automated checks.

Authentication flow

  1. The browser requests GET /api/auth/session to obtain session state and a CSRF token.
  2. POST /api/auth/login validates input and evaluates the selected safe or unsafe authentication path.
  3. On success the server rotates the session ID, stores the authenticated identity, and issues a fresh CSRF token.
  4. Protected requests reload the user from the database, then check active status, role, and ownership.

Isolation

Each variant has a fixed server-side configuration, separate database, session cookie name, and session secret. Database ports are not published to the host. Cookies are HttpOnly and SameSite=Strict; write requests require CSRF and same-origin checks.
