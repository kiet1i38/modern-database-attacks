Mục tiêu của trang này: giải thích vì sao project có một đoạn code cố ý không an toàn để minh họa, nhưng khi tắt lab thì secure route vẫn không bị bypass.

Kết luận ngắn: project không làm toàn bộ ứng dụng mất bảo mật. Nó tách thành secure route và một lab route local-only. Lab route mới chứa query cố ý dễ bị operator injection; secure route không dùng query password do client kiểm soát.

1. Ba trạng thái chạy của project

Secure-only

LAB_MODE=false, là chế độ mặc định của Docker Compose.

Secure login hoạt động; lab endpoint bị disable hoặc trả 404.

Local lab

LAB_MODE=true, chỉ dùng với dữ liệu synthetic trên máy local.

Secure route vẫn an toàn; lab route cho phép quan sát 6 payload đã allowlist.

Production

Nếu NODE_ENV=production, lab route bị chặn ngay cả khi có bật flag.

Lab cũng yêu cầu request loopback, không phải public endpoint.

4. Secure mode: vì sao object không bypass được

Secure mode dùng password như một giá trị scalar và verify hash trong application code. Password do client gửi không được đưa vào MongoDB filter.

// secure.routes.js
const input = validateSecureLoginBody(request.body);
const result = await authenticateSecure(dbClient.db(), input);
// auth.service.js — secure path
const user = await database.collection(COLLECTIONS.USERS).findOne({
  username,
  active: true
});

if (!user || !verifyPassword(password, user.passwordHash)) {
  return { authenticated: false };
}
  1. validateSecureLoginBody yêu cầu username và password là string.
  2. Object, array, number, boolean, null và field thừa bị trả 400 INVALID_INPUT.
  3. MongoDB chỉ tìm user theo username và active.
  4. Password được kiểm tra bằng hash scrypt trong application code.
  5. Vì object không đi qua validation nên không thể trở thành MongoDB operator trong secure query.
Khi LAB_MODE=false, đây là đường login duy nhất có thể dùng cho demo bình thường. Payload object không bypass được đường này.

5. Lab mode: đoạn code cố ý dễ bị tấn công

Lab route không đại diện cho code production. Nó được giữ lại để chứng minh lỗi xảy ra khi application đưa một object do client kiểm soát vào query MongoDB.

// lab.routes.js
const input = validateLabLoginBody(request.body);
const result = await observeLabLogin(dbClient.db(), input);
// auth.service.js — intentionally unsafe lab path
const user = await database.collection(COLLECTIONS.LAB_USERS).findOne({
  username,
  password
});

Nếu password là string, MongoDB xử lý nó như equality value. Nếu password là object có key operator, MongoDB có thể diễn giải object đó như predicate cho field password. Đó là nguyên nhân lab route có thể trả authenticated success mà không cần password scalar đúng.

Điểm quan trọng: validator vẫn allowlist và giới hạn payload. Project không mở một generic query injection cho mọi operator.

6. Sáu operator đang được demo

OperatorPayload trong passwordÝ nghĩa queryKết quả local mong đợi
$gt{ "$gt": "" }Password lớn hơn chuỗi rỗng.200, authenticated.
$gte{ "$gte": "" }Password lớn hơn hoặc bằng chuỗi rỗng.200, authenticated.
$ne{ "$ne": "not-the-password" }Password khác một giá trị không phải password thật.200, authenticated.
$regex{ "$regex": ".*" }Regex match chuỗi password.200, authenticated.
$nin{ "$nin": ["not-the-password"] }Password không nằm trong danh sách.200, authenticated.
$exists{ "$exists": true }Field password tồn tại.200, authenticated.
Lưu ý về đề bài: { "gt": "" } không có dấu $ không phải cú pháp operator MongoDB. Project dùng cú pháp thật { "$gt": "" }; hình dạng không có $ được test như invalid input.

7. Vì sao lab route không bảo vệ được

  1. Password trong lab collection là plaintext synthetic để query operator có thể so sánh trực tiếp.
  2. Client được phép gửi password dưới dạng object thay vì scalar string.
  3. Service dùng trực tiếp password trong findOne.
  4. MongoDB không biết field đó “đáng lẽ là password”; nó chỉ thấy một query predicate hợp lệ.
  5. Nếu predicate match document, service trả authenticated: true.
Đây là lỗi thiết kế được mô phỏng có chủ đích. Không được copy observeLabLogin vào authentication production và không được bật lab trên hệ thống public.

Vì vậy câu “tắt lab thì phần bảo mật không bị tấn công” là đúng trong phạm vi code hiện tại: đường secure không nhận object và đường vulnerable bị disable.

10. Docker: chạy secure và chạy lab

Secure-only mặc định

docker compose up --build -d
docker compose run --rm app node scripts/seed.js

Ở chế độ này, chọn Secure comparison. Không kỳ vọng operator payload hoạt động vì lab route chưa được bật.

Bật lab cho buổi demo local

docker compose down
docker compose -f docker-compose.yml -f docker-compose.lab.yml up --build -d
docker compose -f docker-compose.yml -f docker-compose.lab.yml run --rm app node scripts/seed.js --lab

File docker-compose.lab.yml chỉ override LAB_MODE=true; nó không làm secure route thành vulnerable route.

Cleanup

docker compose down

Sau khi demo, tắt lab hoặc dừng stack. Không public port MongoDB và không dùng dữ liệu thật.

12. Checklist thuyết trình / demo

  1. Chạy secure-only, login đúng password và sai password.
  2. Gửi object vào secure route; cho thấy kết quả 400 INVALID_INPUT.
  3. Bật lab local và seed lab_users.
  4. Chọn từng operator trong UI; cho thấy request password là object thật.
  5. Giải thích query lab khác query secure ở điểm nào.
  6. Nhấn mạnh lab route chỉ là controlled observation, không phải authentication implementation.
  7. Tắt stack hoặc tắt lab sau khi thu evidence.

13. Giới hạn an toàn

Chỉ chạy với localhost, dữ liệu synthetic và database do nhóm sở hữu. Không dùng các payload này vào website, tài khoản hoặc database của người khác.

  • validation.js — input validation và operator allowlist.
  • lab.routes.js — guarded lab endpoint.
  • secure.routes.js — secure login endpoint.
  • public/app.js — browser payload selection.
